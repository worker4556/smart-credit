# Smart Credit — «Маршрут к одобрению»

Умный кредитный кабинет предпринимателя — прототип цифрового кредитного конвейера для малого и микробизнеса (Альфа-Хак 2026).

Предприниматель описывает задачу, заранее видит реалистичную сумму и полную стоимость в рублях, подаёт заявку и понимает
каждый следующий шаг. Если нужную сумму сейчас получить нельзя, он получает маршрут: что мешает, что сделать и примерно
когда пробовать снова. Банк обрабатывает ту же заявку по тем же правилам и вручную разбирает только исключения.

## Для жюри

**Онлайн-стенд:** _ссылка появится после деплоя_ — без установки, вход `p1`…`p5` / `demo`. Как развёрнут: [docs/deploy.md](docs/deploy.md).

### Запуск

Нужны Docker Desktop (Windows, macOS) или Docker Engine с Compose v2 (Linux), **8 ГБ оперативной памяти** и
**~12 ГБ свободного места**. Видеокарта не нужна. Интернет нужен только для первой сборки.

```bash
git clone https://github.com/worker4556/smart-credit.git && cd smart-credit
cp .env.example .env
docker compose up --build -d
```

Первая сборка занимает 10–30 минут: дольше всего скачивается языковая модель для образа `llm` (~1,4 ГБ). Повторный
запуск — секунды. Готовность: `docker compose ps` показывает все пять сервисов `healthy`/`Up`. Затем откройте
**http://localhost:3000**.

- Если памяти мало, LLM можно выключить: `OLLAMA_URL=` в `.env`. Всё продолжит работать, тексты будут по шаблонам.
- Если GitHub-пакеты проекта открыты для вашей учётки, можно не собирать, а скачать готовые образы:
  `docker compose pull && docker compose up -d`.
- Остановить: `docker compose down`. Начать демо с чистого листа: войти `admin` → «Сбросить демо-данные».

Языковая модель с открытыми весами (`qwen3:1.7b`) работает локально внутри образа `llm`. Она только пересказывает
факты, посчитанные правилами, и разбирает свободную фразу клиента — решений она не принимает.

### Сценарий проверки (7–10 минут)

Шаги клиента: **Цель → Компания → Финансы (можно пропустить) → Предложение → Документы → Отправка → Статус**. Сумма и срок задаются на шаге «Цель»; ИНН подставляется из учётки. Для скорости демо ответы персоны на шаге «Финансы» предзаполнены — их можно изменить.

1. **`p1`** — на шаге «Цель» напишите «Нужно 850 тысяч на 2 года на закупку к сезону» → «Разобрать», подтвердите компанию, пройдите
   шаги и отправьте → одобрение → «Принять условия» → «Подписать договор» → «Деньги перечислены».
2. **`p2`** — 3 000 000 ₽ на 18 мес.: предоценка покажет вилку 2,55–2,85 млн, отправьте → заявка у специалиста.
   Войдите **`specialist`** → откройте заявку → код причины `L_TURNOVER` → «Сохранить решение». Снова **`p2`**:
   «хотели 3 млн — можем 2,85 млн» и маршрут, построенный от решения специалиста.
3. **`p3`** — предоценка покажет низкий шанс и цветные причины, отправьте → отказ. Отметьте шаги маршрута — он
   пересчитается. В «Помощи» спросите «почему отказали?» и «что такое сальдо ЕНС?».
4. **`p5`** — пропустите «Финансы», отправьте → «нужны данные» → загрузите
   [`docs/demo-files/vypiska-p5-demo.pdf`](docs/demo-files/vypiska-p5-demo.pdf) → одобрено.

Все сценарии с ожидаемыми результатами по шагам — [docs/test-scenarios.md](docs/test-scenarios.md).

### Переменные окружения

Все — в [.env.example](.env.example); для демо менять ничего не нужно.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `OLLAMA_URL` | `http://llm:11434` | адрес LLM; пусто — LLM выключена, тексты по шаблонам |
| `OLLAMA_MODEL` | `qwen3:1.7b` | любая модель с открытыми весами |
| `LLM_TEXT_TIMEOUT_SECONDS`, `LLM_INTENT_TIMEOUT_SECONDS` | 30, 15 | сколько ждать LLM до отката на шаблон |
| `ML_SERVICE_TOKEN` | пусто | служебный токен backend ↔ ml |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | `smartcredit`, `postgres`, `postgres` | база данных |
| `SECRET_KEY` | демо-значение | подпись JWT; заменить вне демо |
| `CORS_ORIGINS` | `http://localhost:3000,http://localhost:5173` | откуда разрешены запросы к API |

## Как внедрить в банке

Скоринг здесь — явная балльная карта на правилах (`ml/config/policy.yaml`), а не «чёрный ящик»: так требуют
объяснимость для клиента и прослеживаемость решений для специалиста. Веса подобраны под синтетические данные; на
синтетике карта различает заёмщиков с Gini 0,46 и стабильна ([docs/model-validation.md](docs/model-validation.md)).

| Что банк меняет | Что остаётся как есть |
|---|---|
| Веса, пороги, продукты и ставки — в `ml/config/*.yaml`, без правки кода | Маршрут к одобрению: шаги клиента, сроки, «ускорить нельзя», пересчёт |
| Калибровка: `python -m validation.run` на своей истории заявок вместо синтетики → предложенные веса | Единый справочник причин: код → текст клиенту → шаг → срок |
| Моки реестров и БКИ → реальные интеграции в бэкенде | Объяснения и помощник на локальной LLM с проверкой каждого ответа; 115-ФЗ — только шаблон |
| Модель LLM — любая с открытыми весами (`OLLAMA_MODEL`) | Одна модель для предоценки, решения и маршрута: прогноз не расходится с решением |

Для эксплуатации: аудит каждого решения (версия политики, хэш входа, время), метрики Prometheus `GET ml:8001/metrics`,
сквозной `X-Request-ID`, служебный токен между бэкендом и ML (`ML_SERVICE_TOKEN`), healthcheck у каждого сервиса.

## Как работаем

1. `git pull --rebase` перед началом работы и перед каждым пушем.
2. Каждый работает в своей папке; общие файлы (`docker-compose.yml`, `docs/`) меняем, предупредив команду.
3. Изменения API — сначала в `docs/api-contract.md`, потом в коде.
4. Рабочие материалы команды (дизайн, планы, задания, выдержки из документов аналитиков) — в [docs/team/](docs/team/README.md); это не часть сдачи.
