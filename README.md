# Smart Credit — «Маршрут к одобрению»

Умный кредитный кабинет предпринимателя для малого и микробизнеса. Прототип для Альфа-Хак 2026.

> **Для жюри.** Версия для проверки — тег **`v1.8-jury`**. Онлайн-стенд: **http://178.154.251.9:3000** — вход `p1`…`p5`, `zsk`, `specialist`, `admin` (пароль `demo`). Запуск у себя — раздел «Запуск» ниже.

**Коротко.** Предприниматель описывает задачу своими словами и **до подачи** видит шанс, реалистичную сумму и полную стоимость в рублях. Если нужную сумму сейчас получить нельзя, вместо тупикового отказа он получает **маршрут**: что мешает, что сделать и примерно когда пробовать снова. Банк обрабатывает ту же заявку по тем же правилам и вручную разбирает только исключения.

---

## Какую боль решаем

| Боль предпринимателя | Подтверждение | Что делает продукт |
|---|---|---|
| Отказ без причины — непонятно, что исправлять и когда возвращаться | Отказ получают больше половины обратившихся, часто без объяснения (Корпорация МСП) | Причина из единого справочника и **маршрут**: шаги со сроком и вкладом в оценку, пересчёт по отметкам, честное «ускорить нельзя» |
| До подачи не знаешь шанса и суммы — узнать можно только рискнув кредитной историей | Сбер считает «кредитный потенциал», но не объясняет, почему лимит такой | **Предоценка** без запроса в БКИ: шанс, вилка суммы, что тянет вниз |
| «Одобрено» оказывается не одобрением | Кейс ЦБ № 51, запрет FTC для Credit Karma, отзывы клиентов | Слово «одобрено» — только после решения; предоценка подписана «это оценка, а не решение банка» |
| Неожиданная стоимость | Большинство жалоб — на рост стоимости в процессе: ставка, просрочка | Полная стоимость в рублях до согласия и «погода по кредиту»: что будет при росте ставки и просрочке |
| Частичное одобрение читается как отказ | — | Небинарные исходы: одобрено · иные условия («хотели 3 млн — можем 2,85 млн») · нужны данные · отказ; 115-ФЗ — отдельно |

Для банка: меньше заведомо неодобряемых заявок у андеррайтера, данные вводятся один раз, к специалисту попадают только исключения с готовым досье, отказник возвращается в этот же банк.

Источники и доказательная база — [docs/01-research/discovery.md](docs/01-research/discovery.md).

## Почему одна фича, а не набор

Предоценка, решение и маршрут считаются **одной моделью** по одной политике. Если прогноз и решение считать разными моделями, прогноз превращается в обещание, которое банк не выполнит. Поэтому «Маршрут к одобрению» — не три экрана, а одна механика на всём пути клиента:

```
Задача словами → Предоценка до подачи → Подача → Решение с причиной → Маршрут → Новая заявка
                      └──────────── одна балльная карта и одни правила ────────────┘
```

Мы сознательно не стали делать «ещё один калькулятор» или чат-бот: зарубежный опыт показывает, что ценность не в том, куда направить отказника (конверсия британской схемы переадресации — 5,2%), а в том, **что исправить и за какой срок**.

## Как это работает

| Кто | Что видит и делает |
|---|---|
| **Клиент** | Цель → Компания → Финансы (можно пропустить) → Предложение → Документы → Отправка → Статус. Данные компании подтягиваются по ИНН, клиент только подтверждает |
| **Банк, автоматически** | Проверки полноты и данных → балльная карта (9 факторов, 100 баллов) → решение по правилам продукта → причины и маршрут |
| **Кредитный специалист** | Только исключения: сумма больше 2 млн ₽, пограничная оценка, недоступный движок. Досье с баллами и лимитами, решение — только с кодом причины |

**ИИ — усилитель, а не опора.** Локальная языковая модель с открытыми весами (`qwen3:1.7b`) только разбирает фразу клиента и пересказывает уже посчитанное. Решений она не принимает; каждый её ответ проверяется, и при сомнении показывается шаблон. Без модели всё работает.

## Запуск

Нужны Docker Desktop (Windows, macOS) или Docker Engine с Compose v2 (Linux), 8 ГБ оперативной памяти и около 12 ГБ на диске. Видеокарта не нужна.

```bash
git clone https://github.com/worker4556/smart-credit.git && cd smart-credit
cp .env.example .env
docker compose up --build -d
```

Первая сборка — 10–30 минут (скачивается языковая модель, ~1,4 ГБ), повторный запуск — секунды. Когда `docker compose ps` показывает все сервисы `healthy` / `Up`, откройте **http://localhost:3000**.

- Мало памяти — выключите LLM: `OLLAMA_URL=` в `.env`, тексты пойдут по шаблонам.
- Остановить: `docker compose down`. Начать демо заново: войти `admin` → «Сбросить демо-данные».
- Переменные окружения — в [.env.example](.env.example), для демо менять ничего не нужно:

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `OLLAMA_URL` | `http://llm:11434` | адрес локальной LLM; пусто — LLM выключена, тексты по шаблонам |
| `OLLAMA_MODEL` | `qwen3:1.7b` | любая модель с открытыми весами |
| `LLM_TEXT_TIMEOUT_SECONDS`, `LLM_INTENT_TIMEOUT_SECONDS` | 30, 15 | сколько ждать LLM до отката на шаблон |
| `ML_SERVICE_TOKEN` | пусто | служебный токен backend ↔ ml |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | `smartcredit`, `postgres`, `postgres` | база данных |
| `SECRET_KEY` | демо-значение | подпись JWT; заменить вне демо |
| `CORS_ORIGINS` | `http://localhost:3000,http://localhost:5173` | откуда разрешены запросы к API |

- Версии зафиксированы: `backend/uv.lock`, `ml/uv.lock`, `frontend/package-lock.json`, `ml/.python-version`, версии базовых образов в `Dockerfile`.

## Демо-учётки

Пароль у всех — `demo`.

| Логин | Кто | Что покажет |
|---|---|---|
| `p1` | Ольга, ИП, кофейня | Одобрение 850 000 ₽ → подписание → выдача |
| `p2` | ООО «Полка», маркетплейсы | 3 млн → специалист → «хотели 3 000 000 — можем 2 850 000 ₽» |
| `p3` | Тимур, ИП, автосервис | Отказ из-за налогового долга → маршрут ~3 мес. → новая заявка |
| `p4` | Марина, ИП, студия маникюра | Отказ по кредитной истории → честное «~8 мес., ускорить нельзя» |
| `p5` | Андрей, ИП, стройматериалы | «Нужны данные» → загрузка выписки → одобрен овердрафт 300 000 ₽ |
| `zsk` | ООО с красным уровнем ЗСК | Приостановка по 115-ФЗ — некредитная причина, маршрута нет |
| `specialist` | Кредитный специалист | Очередь исключений, досье, решение с кодом причины |
| `admin` | Ведущий демо | Состояние сервисов, все заявки, сброс демо-данных |

**Быстрая проверка.** На шаге «Предложение» по умолчанию выделен «★ Лучший вариант»; чтобы оставить свою сумму, выберите «Как просили».

1. **`p1`** — «Нужно 850 тысяч на 2 года на закупку к сезону» → пройти шаги → одобрено → «Принять условия» → «Подписать договор» → «Деньги перечислены».
2. **`p2`** — 3 000 000 ₽ на 18 мес., вариант «Как просили» → заявка у специалиста. Войти `specialist` → код причины `L_TURNOVER` → «Сохранить решение». Снова `p2`: «хотели 3 млн — можем 2,85 млн» и маршрут от решения специалиста.
3. **`p3`** — 1 200 000 ₽ на 24 мес. → отправить → отказ. Отметить шаги маршрута → «Подать новую заявку». В «Помощи» спросить «почему отказали?».
4. **`p5`** — на шаге «Финансы» ввести выручку 900 000 ₽, вариант «Как просили» — овердрафт 300 000 ₽ → «нужны данные» → загрузить [docs/demo-files/vypiska-p5-demo.pdf](docs/demo-files/vypiska-p5-demo.pdf) → одобрено.

Все сценарии с ожидаемыми результатами по шагам — [docs/test-scenarios.md](docs/test-scenarios.md).
