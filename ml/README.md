# ml — движок одобрения «Маршрут к одобрению»

Stateless FastAPI-сервис на порту **8001**, вызывается только backend. Контракт — [docs/api-contract.md, раздел C](../docs/api-contract.md#c-ml--движок-одобрения-httpml8001).

**Одна модель правил считает всё:** предоценку (шаг 3), скоринг (Б3), решение (Б4), причины и маршрут. Поэтому прогноз,
решение и маршрут не противоречат друг другу. Веса, пороги, формулы лимита, ставки и справочник причин —
в [config/](config/), не в коде. Это не ML-модель, а явная балльная карта: кейс допускает «набор формализованных правил,
балльную модель», а объяснимость для клиента и специалиста важнее.

## Структура

```
config/policy.yaml    9 факторов (100 баллов), стопы, правила решения, продукты, предоценка, маршрут
config/reasons.yaml   единый справочник причин: текст клиенту, категория, шаг маршрута, срок, эффект шага
service/
  scoring.py   Б3: баллы по факторам, стоп-факторы
  decision.py  лимит по продукту, Б4 (порядок правил), предложения 1–3, предоценка
  route.py     маршрут: шаги по «баллы / месяцы», время, окно 90+, пересчёт
  finance.py   аннуитет, полная стоимость в ₽, овердрафт
  intent.py    фраза клиента → цель, сумма, срок, продукт (правила + LLM)
  explain.py   тексты клиенту: шаблоны + пересказ LLM с проверкой
  llm.py       клиент Ollama (open-weights), опционален
  main.py      эндпоинты
fixtures/personas.json  синтетика P1–P5 и тест-аккаунт ЗСК = приёмочные сценарии
eval/                   30 + 15 фраз для проверки ассистента (гипотеза Г4)
tests/                  pytest
```

## Модель

| Слой | Фактор | Макс. | Метрика | Код причины |
|---|---|---|---|---|
| Бизнес | Регулярность оборотов | 20 | коэф. вариации поступлений за 6 мес | `B_TURNOVER` |
| | Долговая нагрузка | 15 | платежи бизнеса / оборот | `B_DEBT_RATIO` |
| | Возраст бизнеса | 10 | мес. | `B_AGE` |
| | Сумма к обороту | 10 | сумма / месячный оборот | `B_AMOUNT` |
| | Отрасль | 8 | группа риска по ОКВЭД | `B_INDUSTRY` |
| | Суды и ФССП | 7 | сумма исп. производств | `B_COURTS` |
| | Срок РКО | 5 | мес. | `B_RKO` |
| Владелец | Кредитная история | 15 | макс. просрочка за 24 мес (до подачи — со слов) | `O_HISTORY` |
| | Личная нагрузка | 10 | личные платежи / оборот, кредитки ≥ 50% | `O_DEBT` |

**Решение (порядок):** 115-ФЗ → нужны данные (документ, расхождение оборота > 30%) → стоп-факторы → баллы ≥ 70 и лимит ≥ суммы
→ одобрено; иначе иные условия (лимит, ×0,75 при 60–69, ×0,5 при 50–59, или другой срок) → баллы < 50 — отказ.
Специалист: сумма > 2 млн, баллы 50–59, расхождение не устранено, клиент оспорил.

**Маршрут:** временные окна (90+ за 12 мес., возраст < 3 мес.) задают минимальный срок; устранимые стопы — обязательные шаги;
затем жадно по «баллы / месяцы», пока прогноз на горизонте не дойдёт до 70. Время само двигает возраст бизнеса и срок счёта.
Если сумму держит оборот — шаг `L_TURNOVER` с целевым оборотом, без обещаний ростом баллов; срок по темпу — только если тренд выражен.

## Локальная LLM

Опциональна (Should): без неё всё работает. Модель — **Qwen3 4B** (открытые веса, Apache 2.0) через Ollama, меняется `OLLAMA_MODEL`.

| Где | Что делает | Защита |
|---|---|---|
| `/v1/intent` | понимает цель, выбирает сумму среди найденных | сумма и срок принимаются, только если такие числа есть во фразе; клиент подтверждает поля; не нашли — форма |
| `/v1/explain` | пересказывает шаблонный текст простым языком | нет чисел, которых нет в шаблоне; нет кодов; нет «одобрено» вне одобрения и обещаний; иначе — шаблон |
| 115-ФЗ | — | LLM не вызывается, только шаблон |

LLM никогда не принимает решение, не считает баллы, суммы и сроки.

## Команды

```bash
uv sync
uv run uvicorn service.main:app --reload --port 8001   # Swagger: http://localhost:8001/docs
uv run pytest
uv run python -m eval.run_intents            # 30 фраз (правила настраивались на них)
uv run python -m eval.run_intents holdout    # 15 отложенных фраз
OLLAMA_URL=http://localhost:11434 uv run python -m eval.run_intents holdout   # с LLM
```

Из корня репозитория: `docker compose up --build` (без LLM) или `docker compose --profile llm up --build`
с `OLLAMA_URL=http://ollama:11434` в `.env` (первый запуск скачивает веса модели).
