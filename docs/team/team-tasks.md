**спецификация + `ml/config/*.yaml` главнее**, «Макет заявки» используем для текстов и словаря простых слов.

## Как всё соединяется

```
frontend ──REST──► backend ──HTTP──► ml   (precheck / decision / route / explain / intent)
                     │   └──HTTP──► mocks (счёт в Альфе, ЕГРЮЛ/ЕГРИП, ФНС, ФССП, арбитраж, БКИ, ЗСК)
                     └──SQL──► postgres
```

Три правила интеграции:

1. **Backend не считает баллы, лимиты, причины и маршрут.** Он собирает `Applicant` (раздел C контракта), отправляет в `ml`
   и **сохраняет ответ целиком** (JSONB). Решение по статусу backend принимает только по `outcome` и `specialist.required`.
2. **Объекты `ml` приходят на фронт как есть.** `Precheck`, `Decision`, `Route`, `Explanation` вкладываются в ответы backend без
   переименования полей. Фронт рисует их напрямую — одна схема на всю систему, типы генерируются из OpenAPI.
3. **Фронт никогда не ходит в `ml` и `mocks` напрямую.**

### Как backend собирает `Applicant`

| Блок `Applicant` | Откуда берёт backend | Когда |
|---|---|---|
| `request` | шаги 1 и 4 заявки (продукт, сумма, срок, поручитель) | всегда |
| `company` | моки ЕГРЮЛ/ЕГРИП, «Прозрачный бизнес», ФССП, арбитраж; `zsk_level` — мок ЗСК | реестры — с шага 2; ЗСК — только на Б2 |
| `account` | мок «счёт в Альфе»: обороты по месяцам, срок РКО, долг и платежи бизнеса; `external_turnover_monthly` — из загруженной выписки | с шага 2 |
| `owner` | **до подачи**: 2 ответа клиента, `source: SELF_REPORTED`; **после подачи**: мок БКИ, `source: BKI` | шаг 2 / Б2 |
| `checks` | заявленная выручка, недостающие документы, «расхождение не устранено», «клиент оспорил» | Б1 |

Готовые входы всех персон: `ml/fixtures/personas.json` (`precheck_owner` — ответы до подачи, `decision` — данные после Б2,
`statement_external_turnover` — что «распознаётся» из выписки P5). **Моки должны отдавать ровно эти данные по ИНН персоны.**

### Как `outcome` превращается в статус заявки

| Ответ `ml /v1/decision` | Статус |
|---|---|
| `specialist.required = true` (любой `outcome`) | **У специалиста** (`outcome` — рекомендация системы) |
| `APPROVED` | **Одобрена** |
| `COUNTER_OFFER` | **Иные условия** |
| `INFO_REQUESTED` | **Нужны данные** |
| `REJECTED` | **Отказ** + backend сразу строит маршрут (`/v1/route`) |
| `SUSPENDED_115FZ` | **Приостановлена по 115-ФЗ**, маршрут не строится |

| `GET /applications/{id}/documents/checklist` | шаг 5: только недостающее | — |

## Frontend — задания

Стек: React + TypeScript + Vite, React Router, TanStack Query. Типы — из OpenAPI backend (`openapi-typescript`).
Пока backend не готов — работать на JSON из `ml/fixtures` и примерах раздела C контракта (объекты те же).

### F1. Каркас и дизайн-система (день 1)
- [ ] Токены: белый фон, чёрный текст, светло-серые панели, **красный — только главная кнопка и ключевые точки маршрута**,
      **лайм — только пиксельный высотомер и отметки «готово»**. Контраст ≥ 4,5:1, цвет дублируется словом или иконкой,
      `prefers-reduced-motion` отключает анимации. Логотип, 3D и шрифт Альфы не используем.
- [ ] Вход по демо-аккаунтам (карточки персон), роутинг клиент / специалист, прокси `/api` на backend.

### F2. Заявка из 6 шагов (день 2–3) — один вопрос на экране, прогресс «Шаг N из 6»
| Экран | Что показывает | Данные |
|---|---|---|
| 1. Задача | поле ассистента + **всегда** форма-фолбэк (цель, сумма, срок); подтверждение распознанных полей | `Intent` (`missing` → какие поля спросить) |
| 2. Компания и владелец | найденная компания и обороты (только подтвердить) + 2 вопроса: просрочки за 2 года, личные платежи | lookup |
| 3. **Предоценка** | высотомер-**вилка**, шанс, полная стоимость в ₽, до 4 причин, кнопки «продолжить / уменьшить сумму / открыть маршрут без подачи» | `Precheck`: `amount_range` = высота, `requested_amount` = вершина, `cost.full_cost`, `reasons[].text`, `disclaimer` дословно |
| 4. Предложение | 1–3 варианта | `Precheck.offers[]` (`kind`, `amount`, `term_months`, `cost`) |
| 5. Документы | чек-лист только недостающего, статусы, загрузка | checklist |
| 6. Сводка и согласия | резюме с «Изменить» + 2 согласия, без них отправка недоступна | черновик |
- [ ] Автосохранение каждого шага, «Продолжить с шага N».

### F3. Трекер и исходы (день 3)

- [ ] Принять / изменить в пределах предложения / отклонить; подписание и выдача (демо).

### F4. Маршрутная карта — главный экран продукта (день 4)

- [ ] Честные состояния по `holds`: `TIME_WINDOW` — «ускорить нельзя», `TURNOVER` — «сумму держит оборот», `NO_ROUTE` — так и пишем.
- [ ] `status = READY` → кнопка «Подать новую заявку». Главная кабинета: карта + активные заявки и маршруты.

### F5. Кабинет специалиста (день 4)
