## Начало
1. BA и команда определяют один сквозной сценарий демо и исключения из MVP.
2. Все согласуют документы архитектуры и API; неизвестные решения остаются открытыми.
3. Frontend и backend согласуют синтетические фикстуры, чтобы работать параллельно.
4. ML/DS фиксирует источник данных, допустимое использование, разбиение и метрику; baseline предшествует сложной модели.
5. Стек и команды запуска фиксируются отдельным архитектурным решением. Только затем настраивается среда приложения.

## Доска
Колонки: Backlog → Ready → In progress → Review → Done. Поля: Role, Priority (P0/P1/P2), Owner, Demo milestone. В issue храните зависимости и критерии готовности; один ведущий исполнитель на задачу, не более одной основной активной задачи на человека.
Blocked — пометка с причиной и необходимым действием, а не безымянная очередь ожидания.

Каждые 2–3 часа: короткая синхронизация по сквозному сценарию, блокерам и изменениям контракта. Перед демо — совместная проверка с чистого запуска и фиктивными данными.

## Начальный backlog
- BA: утвердить MVP и сценарий демо (готово: проверяемые критерии и исключения).
- UX: подготовить сценарий и все состояния экрана (зависит от MVP).
- Backend + frontend + ML: согласовать API и фикстуры (зависит от сценария).
- ML: описать допустимые данные, baseline и оценку качества.
- Команда: выбрать стек и зафиксировать команды локального запуска.
- Все: собрать один сквозной сценарий и провести репетицию демо.

Done означает: критерии выполнены, проверки указаны, PR прошёл независимое review и слит, документы актуальны, результат можно показать.
