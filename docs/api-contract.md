# API-контракт: соглашение до реализации

Статус: черновик, не реализованный API. Стек, транспорт, URL, методы, поля и модели данных не выбраны. Этот документ — точка совместной работы backend, frontend и ML/DS; он не обещает существующих endpoint-ов.

## Как принять контракт
1. BA фиксирует сценарий и смысл результата; UX — необходимые состояния.
2. Backend и frontend заполняют таблицу операции ниже и добавляют синтетические примеры.
3. ML/DS согласует вход модели, результат, версии и ограничения.
4. Участники подтверждают PR; статус меняется на «согласован», примеры становятся общими фикстурами.
5. После выбора HTTP или другого транспорта добавляется машиночитаемая схема подходящего формата отдельным PR.

## Обязательные случаи для фикстур
- Корректный минимальный ввод и успешный результат.
- Пропущенное обязательное поле, неверный тип и граничные значения.
- Отсутствующие данные: разница между отсутствием поля, null и нулём.
- Недоступность/таймаут модели, неизвестная ошибка без внутренних деталей.
- Повторная отправка запроса и состояния loading/error/retry/success.

Вероятность, скоринг, рекомендация и бизнес-решение — разные сущности; нельзя использовать их как взаимозаменяемые без определения BA и ML/DS. Не фиксировать пороги одобрения до согласования.

## Изменения
Изменение поля или его смысла требует PR с перечнем потребителей, обновлением фикстур и планом совместимости. Не менять контракт молча ради одной реализации. До его согласования интерфейс использует явно помеченные моки.
