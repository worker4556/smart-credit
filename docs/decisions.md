# Решения и допущения

Основание — спецификация MVP «Маршрут к одобрению» (20.10.2026) и кейс Альфа-Банка. Ниже то, что спецификация
не фиксирует и что решено при реализации. Всё — демонстрационные допущения; значения в `ml/config/`.

## ML / движок одобрения (20.10.2026)

| # | Решение | Почему |
|---|---|---|
| 1 | Скоринг, решение (Б4), предоценка и маршрут считаются в `ml` одной моделью; backend хранит результат и двигает статусы | Требование «одна модель для всех этапов»: прогноз и решение не расходятся |
| 2 | Обученная модель (WOE + логрегрессия) удалена; балльная карта на правилах | Спецификация: «скоринг на правилах и баллах, а не на ML»; персоны требуют точных цифр |
| 3 | Шкалы баллов внутри 9 факторов (пороги метрик) подобраны так, чтобы P1–P5 давали цифры спецификации | Спецификация задаёт только максимумы факторов |
| 4 | Регулярность оборотов = коэффициент вариации поступлений за 6 мес; оборот = счёт в Альфе + подтверждённая выписка | Одна метрика для скоринга, лимита и проверки расхождения |
| 5 | Кредитки ≥ 50% лимита снимают 8 баллов личной нагрузки | Шаг маршрута P3 «кредитка < 50%, +8» |
| 6 | До подачи «были просрочки» со слов клиента = 9 баллов из 15; стопы БКИ до подачи не проверяются | Предоценка без БКИ |
| 7 | Иные условия при 50–69 баллах: сумма = min(запрос, лимит × 0,75 / 0,5) и ставка выше базовой на +2 / +4 п.п. (причина `R_RISK_PRICE`) — иные условия всегда отличаются от запроса | Одобрение только от 70 баллов; «хотели — можем» должно быть видно |
| 8 | Если лимит держит платёж, а более длинный срок даёт всю сумму, — иные условия «другой срок» | Правило 5: «подходит другой срок» |
| 9 | Вилка предоценки: [−10%; доступная сумма], округление вниз | Пример P2: 2,55–2,85 млн |
| 10 | «Готов к подаче»: нет стопов, ≥ 70 баллов **и** лимит ≥ выбранной суммы | Иначе «готов» вёл бы к иным условиям, а не к вершине |
| 11 | Срок роста оборота считается по тренду, только если тренд выражен (R² ≥ 0,5); иначе «зависит от темпа» | Не рисуем ложный короткий путь |
| 12 | Дополнительные стоп-коды: `S_OVERDUE`, `S_FNS_BLOCK`, `S_LAWSUIT`, `S_AGE`, `S_BANKRUPTCY`, `S_INDUSTRY`, `S_INACTIVE` (ликвидация); 115-ФЗ — `Z_115` | В справочнике спецификации есть только `S_TAX`, `S_90_12` |
| 13 | Оборотный кредит: от 100 000 ₽, 3–36 мес. (как ползунок фронта и «Макет»); овердрафт: от 50 000 ₽, срок всегда 12 мес.; срок вне продукта или сумма ниже минимума → `422` с понятным текстом (backend отдаёт клиенту `400` с полем `field`), без тихой подмены; сумма выше максимума — не ошибка: в решении это иные условия, а калькулятор и «Погода» считают её как есть; шаг лимита 50 тыс. / 10 тыс. | Фронт и ML считают одно и то же |
| 14 | LLM — открытые веса через Ollama, **включена по умолчанию** в `docker compose up`; модель по умолчанию `qwen3:1.7b` (Apache 2.0) — самая лёгкая; окончательный выбор — по замеру `eval/` на MacBook Air M2 в Docker; если по скорости не проходит ни одна — самая лёгкая, LLM остаётся включённой (решение владельца проекта, 20.10) | Жюри запускает на ноутбуке без видеокарты |
| 15 | LLM может выбрать сумму и срок только из чисел, найденных во фразе правилами | «Модель не называет чисел, которых нет на входе» |
| 16 | «Нужны данные» по выручке — только если заявлено **больше** оборота по счёту более чем на 30%; заявлено меньше — банк опирается на счёт | Часть выручки мимо счёта можно подтвердить выпиской; заниженная выручка не повод для запроса |
| 17 | «Погода»: ставка +2 п.п. («например, при плавающей ставке или рефинансировании») и просрочка 30 дней с пени 0,1% в день от просроченной суммы (кредит — один платёж, овердрафт — весь лимит); на решение не влияет | Спецификация: «полная стоимость в ₽ при росте плавающей ставки и при просрочке» |
| 18 | Помощник по заявке на любой стадии (изменено 24.10, раньше — только при отказе и нехватке): до подачи отвечает по предоценке, после — по решению, маршруту и стадии; тема вопроса — правилами, ответ — по фактам решения, маршрута и словаря; LLM только переформулирует, проверка как у пересказа; без истории диалога и без потоковой передачи; 115-ФЗ — фиксированный текст | Модели передаются только тексты, построенные из кодов и параметров по справочнику |
| 19 | Таймауты: LLM внутри `ml` — 30 с на тексты, 15 с на разбор фразы; бэкенд — 40 с на `/v1/explain` и `/v1/assistant`, 20 с на `/v1/intent`, 5 с на остальное | LLM на процессоре; объяснения решения готовятся заранее в фоне |
| 20 | Словарь: 15 терминов «Макета» (раздел 4) дословно + 7 терминов из наших текстов (ЕНС, ФССП, 115-ФЗ и др.) | Один словарь для подсказок и помощника |
| 21 | Термин «ПСК» есть в словаре только как форма слова для поиска («Переплата»), в текстах для клиента его нет; про 115-ФЗ помощник отвечает только фиксированным текстом, даже если спросили как термин; запрошенную сумму модель видит только в вопросе о сумме | Итоговая проверка ветки: правила «не пишем ПСК», «115-ФЗ — только шаблон», «модель не меняет сумму решения» |
| 22 | Проверка карты на 20 000 синтетических компаний с исходом, заданным независимой логистической зависимостью (базовый уровень дефолтов ~8%): Gini 0,46, KS 0,36, PSI 0,001; веса не меняем под калибровку — на них держатся сценарии P1–P5 | Кейс, стр. 14: модели проверяются по различению, точности и стабильности |
| 23 | Аудит решения = версия политики + версия движка + SHA-256 входа + время; метрики Prometheus без внешних зависимостей; служебный токен выключен по умолчанию | Прослеживаемость решений и эксплуатация без усложнения запуска для жюри |
| 24 | Новостной ленты под клиента в MVP нет | Требование попало в текст кейса по ошибке — подтверждено менторами ([mvp-scope.md](02-product/mvp-scope.md)) |
