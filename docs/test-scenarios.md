# Тестовые сценарии

Как проверить решение руками в интерфейсе, запросами из коллекции и автотестами. Подробные карточки персон
(ситуация, данные на входе, истории) — в [06-personas/test-user-maps.md](06-personas/test-user-maps.md).

Пароль всех учёток — `demo`. Каждая учётка клиента — одна компания с одним ИНН: ИНН подставляется из учётки, вводить
его не нужно. Все данные синтетические.

## Как запускать проверки

Стек поднят через `docker compose up --build` (см. [README](../README.md)).

| Что | Команда | Что проверяет |
|---|---|---|
| Сквозной прогон всех персонажей | `python3 scripts/smoke_api.py` | вход → черновик → предоценка → подача → решение → маршрут для P1–P5 и ZSK (только стандартная библиотека Python) |
| Коллекция запросов | `npx newman run docs/postman/smart-credit.postman_collection.json --working-dir .` | 7 папок, 48 запросов, 28 проверок: суммы до рубля, путь специалиста, загрузка выписки. ⚠️ В конце сбрасывает демо-данные — не запускайте во время показа |
| Движок одобрения | `cd ml && uv run pytest` | приёмка по персонам `tests/test_personas.py`, правила, сервис, LLM-обвязка |
| Backend | `cd backend && uv run pytest` | сборка данных для движка, маппинг контрактов, миграции (с `TEST_DATABASE_URL`) |
| Frontend | `cd frontend && npm test` | подсветка фразы, продукт по цели, «как просили», финансы, маршрут на главной |

Коллекцию можно открыть и в Postman: *Import* → `docs/postman/smart-credit.postman_collection.json`, затем запускать
папки по порядку через *Runner*.

## Сценарии в интерфейсе (http://localhost:3000)

Шаги клиента: **Цель → Компания → Финансы (можно пропустить) → Предложение → Документы → Отправка → Статус**. Сумма и срок задаются на шаге «Цель»; ИНН подставляется из учётки. Для скорости демо ответы персоны на шаге «Финансы» предзаполнены — их можно изменить.

### S7а. Помощник на любом этапе

Меню «Помощь» (на узком экране — кнопка ☰ → «Помощь»). Подсказки-вопросы меняются по стадии заявки.

| Стадия | Вопрос | Ожидаемый ответ (по фактам заявки) |
|---|---|---|
| Черновик до предоценки | «Что делать?» | Какие шаги пройти; «Финансы» можно пропустить; предоценка — не решение |
| Черновик после предоценки (`p4`) | «Почему такой шанс?» | Шанс, вилка суммы, что влияет, пометка про кредитную историю, «оценка, а не решение» |
| Черновик (`p2`) | «Почему такая сумма?» | 3 000 000 ₽ выше оценки — есть вариант в пределах 2 850 000 ₽ |
| На проверке / у специалиста | «Когда будет решение?» | Делать ничего не нужно, срок банк не обещает; у специалиста — можно отозвать |
| Одобрено (`p1`) | «Почему одобрили?» | 850 000 ₽ · 43 261 ₽ · 196 774 ₽, 100 баллов из 100, сильные стороны |
| Одобрено | «Что дальше?» | Принять условия → подписать; предложение действует 30 дней |
| Овердрафт одобрен (`p5`) | «Сколько это стоит?» | Лимит, проценты при полном использовании 5 425 ₽ + комиссия 3 000 ₽ |
| Подписано / выдано | «Что дальше?» | Деньги перечисляются / на счёте, платить по графику |
| Любая | «Что такое полная стоимость кредита?» | Объяснение из словаря |
| Отказ, иные условия, нужны данные | «Почему?», «Что делать?» | Как раньше: причины, шаги маршрута, срок |
| 115-ФЗ | любой | Только шаблон, без LLM |

Сначала приходит ответ по шаблону, затем LLM может его переформулировать; если в её тексте появляются новые
числа, обещания или «одобрено» до решения — остаётся шаблон. Автотесты: `ml/tests/test_assistant_good.py`.

## Правила продукта, которые проверяют сценарии

| Правило | Где видно |
|---|---|
| ИНН подставляется из учётки, одна учётка — один ИНН | S1–S6, шаг «Компания» |
| Шаг «Финансы» необязательный | S5, шаг 2 |
| Лучшие предложения выделены: «★ Лучший вариант», «Ниже платёж», «Меньше переплата» | S1, S2, S5 |
| Маршрут только при неопределённости: шанс ниже высокого, сумма выше оценки, отказ, решение специалиста | S1 (нет маршрута), S2, S3, S5 |
| Цвета: 🟢 можно сразу · 🟡 нужно время · 🔴 стоп-фактор | S3, S4, S5 |
| Решение специалиста только с кодом причины, маршрут строится от него | S2 |
| 115-ФЗ не смешан с кредитным отказом | S6 |
