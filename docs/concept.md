# Концепт Smart Credit

> **Предприниматель описывает задачу, а не выбирает продукт. Система по одному ИНН собирает данные сама, ведёт заявку как трекер доставки и объясняет любое решение. Банк видит ту же заявку уже проверенной и разбирает руками только исключения.**

## Боли, которые решаем

| Предприниматель | Банк |
|---|---|
| Не понимает, какой продукт нужен | Заявки на неподходящие продукты |
| Заполняет одно и то же много раз | Неполные и ошибочные данные на входе |
| Не знает, что происходит с заявкой | Обращения «что с моей заявкой?» |
| Получает отказ без объяснения | Андеррайтер тратит время на очевидные кейсы |

## Главная идея — «одна заявка, два окна»

Заявка — единый объект с состоянием, данными и историей.
- **Окно клиента:** простой язык, прогресс, «что нужно от вас».
- **Окно банка:** проверки, скоринг с объяснением, кнопки решений.

Данные вводятся один раз и переиспользуются на всех этапах.

## Пять опор

1. **Подбор от задачи.** «Купить оборудование», «Закрыть кассовый разрыв», «Исполнить контракт» → 1–3 продукта с пояснением «почему вам».
2. **ИНН вместо анкеты.** Реквизиты, ОКВЭД, возраст бизнеса — из ЕГРЮЛ/ЕГРИП и ФНС (моки). Спрашиваем только недостающее: сумма, срок, цель, выручка.
3. **Предварительная оценка до подачи.** Клиент меняет сумму и срок и видит шансы и ориентир ставки, плюс подсказки «что изменить, чтобы шансы выросли» (контрфактические объяснения скоринговой карты). Результат не является решением банка.
4. **Трекер заявки.** Каждый этап виден. Если нужно действие клиента — в кабинете появляется задача. Все уведомления только внутри продукта.
5. **Объяснимое решение.** Одобрено / контрпредложение / дозапрос / отказ — всегда с причинами и следующим шагом.

**Банк:** типовые заявки решаются автоматически, пограничные уходят андеррайтеру с готовым досье (human-in-the-loop).

## Принципы

1. Данные вводятся один раз.
2. Каждый статус отвечает на вопрос «что дальше и от кого».
3. Скоринг ≠ решение: модель оценивает риск, кредитная политика решает.
4. Объяснимость важнее точности: скоринговая карта, а не чёрный ящик.
5. ИИ — усилитель, а не опора: без LLM всё работает.

## Вне MVP (осознанно)

Залоги и поручители, реальная ЭЦП и выдача денег, несколько сотрудников клиента с разными правами, мобильное приложение, реальные внешние интеграции.

## Демо на защите

1. ИП Соколова: задача «купить кофемашину 1,5 млн» → подбор → ИНН → предоценка подсказывает 1,2 млн → подача → трекер → контрпредложение → подписание → «выдано».
2. Кабинет банка: «СтройМонтаж» → досье → дозапрос выписки → у клиента задача → загрузил → одобрено.
3. «Ритм»: мгновенный объяснимый отказ с рекомендацией.
