# llm — локальная языковая модель

Сервис `llm` в `docker-compose.yml`: [Ollama](https://ollama.com) с моделью **Qwen3 1.7B** (`qwen3:1.7b`, Apache 2.0,
открытые веса). Работает на процессоре, видеокарта не нужна. Им пользуется **только сервис `ml`**; фронт и бэкенд
с моделью напрямую не работают.

```
фронт ─► backend ─► ml ─► llm (этот сервис)
                     │
                     └─ проверяет каждый ответ модели; не прошёл или модель недоступна — шаблон
```

## Что делает модель и чего не делает никогда

| Где (эндпоинт ML) | Момент для клиента | Что делает |
|---|---|---|
| `/v1/intent` | Начало заявки: «опишите задачу своими словами» | Понимает цель; сумму и срок берёт только из чисел, найденных во фразе |
| `/v1/explain` | Отказ, иные условия, нужны данные, маршрут | Пересказывает готовый текст решения и маршрута простым языком; вызывается в фоне, заранее |
| `/v1/assistant` | Отказ, иные условия, нужны данные, маршрут | Отвечает на вопросы «почему», «что делать», «когда», «что значит термин» — только по фактам решения и словарю |

**Никогда:** не принимает и не меняет решение, баллы, суммы и сроки; не называет чисел и причин, которых нет на входе;
не обещает одобрение и не пишет «одобрено» вне решения; не пишет «ПСК»; ничего не пишет о 115-ФЗ — там только
фиксированный текст, и модель даже не вызывается. Не используется при одобрении и в предоценке.

Проверка ответа — `ml/service/explain.py → check_llm_text`, тесты — `ml/tests/test_llm.py`, `test_assistant.py`.

## Как запускается

`docker compose up --build` из корня:
1. `llm` поднимает Ollama;
2. при **первом** запуске скачивает модель (~1,4 ГБ) в том `llm-models` — дальше она берётся оттуда;
3. прогревает модель первым запросом;
4. `ml` стартует, не дожидаясь этого: пока модель не готова, `GET ml:8001/health` показывает `llm.ready = false`,
   а все тексты — шаблонные. Как только модель готова, помощник включается сам, без перезапуска.

Требования: 8 ГБ оперативной памяти, ~2 ГБ на диске. Лимит памяти контейнера — 6 ГБ.

## Настройки (`.env` в корне)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `OLLAMA_MODEL` | `qwen3:1.7b` | Модель — одна и та же для `llm` и `ml` |
| `OLLAMA_URL` | `http://llm:11434` | Адрес модели для `ml`. Пусто (`OLLAMA_URL=`) — LLM выключена, всё на шаблонах |
| `LLM_TEXT_TIMEOUT_SECONDS` | `30` | Таймаут пересказа и помощника |
| `LLM_INTENT_TIMEOUT_SECONDS` | `15` | Таймаут разбора фразы |

**Mac для разработки:** Docker на macOS не даёт контейнерам видеокарту, поэтому нативная Ollama в 5–10 раз быстрее:
```bash
brew install ollama && ollama pull qwen3:1.7b && ollama serve
```
и в `.env`: `OLLAMA_URL=http://host.docker.internal:11434`.

## Как выбрать другую модель

Только модели с открытыми весами (условие кейса). Замер на ноутбуке без видеокарты:
```bash
cd ml
OLLAMA_URL=http://localhost:11434 OLLAMA_MODEL=<модель> uv run python -m eval.run_intents holdout
OLLAMA_URL=http://localhost:11434 OLLAMA_MODEL=<модель> uv run python -m eval.run_assistant
```
Пороги: разбор фразы ≥ 80% по всем полям; ответы помощника, прошедшие проверку, ≥ 80%; вопросы не по теме — 100%;
медиана ответа ≤ 30 с. Берём самую лёгкую модель, которая проходит. Новую модель записать в `.env.example`,
`llm/Dockerfile`, `ml/service/llm.py`, `docker-compose.yml`, `THIRD_PARTY_NOTICES.md` — тест
`ml/tests/test_docs_consistency.py` проверит, что везде одна и та же.
